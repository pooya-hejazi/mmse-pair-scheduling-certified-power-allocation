# Frozen comparison protocol — 2026-11-10

The primary question is whether the current practical DP + local SQP search is competitive with source-inspired 2026 power-search components on exactly the same problem. This is NOT an end-to-end reproduction of the Fu or Thu system models or their original objectives. All arms share the labelled-resource fixed-power subset-DP assignment outer loop. The continuous SQP block is local and does not establish global optimality.

## Cases and stopping, fixed before observing results
- Existing phase1-cdl-20261109 cases: CDL A/B/C, K=16, S=8, M=2, separations 0.5, 2, 6, 12 degrees, seeds 2026110901 and 2026110902 (24 paired cases). The archived generator is a CDL-inspired reduced common-model construction, not a fresh standards conformance validation.
- Three arms: DP-SQP (current practical method), DP-Fu-SCA (adapted Fu2026 power minorant), DP-Thu-IDE (adapted Thu2026v1 power evolution).
- Equal 10-second optimization wall-clock budget per arm; equal maximum 2 seconds per continuous-power call; <=8 assignment/power alternations per start; 8 common starts. The per-block limit may truncate IDE generations and cannot establish converged comparisons.
- Shared sequential pairing/uniform feasible first start; seven seeded random pairings and box-feasible random powers, with exact budget repair. Start RNG seed 20261109; refiner RNG seed 20261110. Each arm sees the same complete start list, subject to its deadline.
- Sequential execution, one BLAS/OpenMP thread; cyclic arm order across cases to distribute order effects. No arm runs concurrently with another benchmark arm. Shared model construction/start generation are outside the search budget; candidate checks and DP work are inside. Final independent matrix/scalar/feasibility audit and output serialization are outside, reported separately.
- Deadlines checked inside subset DP every 256 masks (before parity filtering), before/after candidate validation, and inside existing power routines. Work completed after the deadline is not retained. Report actual elapsed time and any overrun, rather than claiming hard real-time enforcement.
- Initial feasible fallback retained if a block times out. Completed starts and DP calls are counted, not the length of the supplied start list. K>20 is explicitly unsupported by this bounded wrapper; no K32 claim or silent approximate substitution.
- Pilot uses the first case and all three arms. Halt if schedule, box, budget, matrix/scalar agreement, deadline accounting, or finite objective fails. Do not tune to its ranking. Pilot is saved separately; the full campaign repeats its case under the identical frozen protocol.

## Wrapper repairs versus historical run_pilot.py
The new wrapper corrects random-start box feasibility via common exact repair, guards exponential DP before allocation (K>20 rejected), checks time inside DP, never retains a post-deadline candidate, and records actual completed starts/blocks. It uses the existing producer.refine local SLSQP block and the unchanged Fu/Thu modules. Common 2-second block caps replace the historical proposed wrapper's 5-second cap for this controlled comparison; results are new measurements, not replacements for historical records.
